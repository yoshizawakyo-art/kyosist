## ラムダ式禁止規約の違反（修正済み）

`main.js` L436 の `response.text().catch()` フォールバックは、名前付き関数 `getFallbackErrorText` / `getStatus` に修正済み（2026-05-03）。
ただし実装は関数内関数（クロージャで `response` を参照）として置かれており、将来的にトップレベルのヘルパーに切り出すとより明快になる。
`kyouCommon.js` L94 に同パターンが残存していないか、次回変更時に確認する。

**Why:** 同一の fetch エラーハンドリングパターンがフロントエンド全体に波及しやすい。
**How to apply:** fetch を使うすべての箇所でアロー関数が混入していないかを確認する。

## UTF-8 BOM の混入

`main.js` の先頭に UTF-8 BOM（EF BB BF）が含まれている。ES module として動作上の問題はないが（主要ブラウザは BOM を無視）、ツールチェーンによっては問題になりうる。エディタの保存設定を BOM なし UTF-8 に統一することを推奨。

## SSE [DONE] ハンドリングのスコープバグ（修正済み）

`sendAgentMessage` 内の SSE 処理で `isDone` フラグが追加され（L345, L359, L392）、`[DONE]` 受信時に `for...of` と `while(true)` の両方が正しく終了するよう修正済み（2026-05-03）。

## キーワードベースのエージェントモード切替

`shouldUseAgentMode()` は部分一致文字列で判定しており、「ニュース」を含む通常の会話がエージェントモードに誤ルーティングされる可能性がある。将来的に精度問題として顕在化しやすい設計上の課題。明示的UIトグルへの移行を検討推奨。

## スキル管理機能（2026-05-03 レビュー）

### セキュリティ上の繰り返しリスク（未修正）
- `SkillCreate.action_url` にSSRFバリデーションがない。Pydantic `field_validator` でスキームと内部IPブロックを必須とすること。
- RLSポリシーが `anon` に全操作（INSERT/DELETE）を許可している。認証導入まで少なくともDELETE/INSERTは `authenticated` に制限すること。

### 繰り返し確認すべきパターン
- `action_method` が `Literal["GET", "POST"]` で制約されていない（`str` のまま）。新しいエンドポイントでも同様のゆるい型定義が生まれやすい。
- Webhookレスポンスがそのままプロンプトに埋め込まれるプロンプトインジェクションリスク。外部APIの返答をLLMの会話履歴に混ぜる箇所では必ずサンドボックスタグを挿入すること。
- スキル名に一意制約がなく、重複登録が可能。`name` カラムに `UNIQUE` 制約を追加することを要検討。

**Why:** スキルはエージェントの行動を決定するデータであり、改ざんやSSRFはシステム全体の信頼性に直結する。
**How to apply:** Webhook URLを受け取るフィールドは必ずバリデーター付きで定義する。
