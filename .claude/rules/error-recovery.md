# エラー・意図しない挙動発生時の対応プロトコル

## 目的

Codex の実装・実行中にエラーや意図しない挙動が発生した場合、根本原因を特定し、同じ問題が繰り返されないようにルール・スキルを更新する。

## トリガー条件

以下が発生した場合、このプロトコルを適用する:

- Codex の出力が設計方針・要件と一致しない（意図しない変更、スコープ外の修正）
- Codex 実行中にエラーが発生する（ツール失敗、環境エラー、トークンリミット）
- `CHECK NG` が2回以上繰り返される（同じ種類の指摘）
- Codex が禁止事項（ラムダ式、`allow_origins=["*"]` 等）を繰り返す
- Codex MCP ツールが失敗する（`--full-auto` エラー等）

## 対応手順

### Step 1: 根本原因の特定

1. エラー内容・意図しない挙動を正確に記録する
2. 以下のいずれかを判断する:
   - Codex への指示が不明確だったか
   - ルールの記載が不足していたか（禁止事項・パターンが未定義）
   - 環境・依存関係・ツールの問題か
3. 再発可能性を評価する

### Step 2: ルール・スキルの更新

根本原因がルールの不備だった場合、`codex exec --dangerously-bypass-approvals-and-sandbox` で以下を更新する（`.md` ファイルは Edit/Write 直接使用も可）:

| 原因の種類 | 更新対象 |
|---|---|
| Codex が禁止事項を繰り返す | `.claude/rules/coding-standards.md` に具体例を追記 |
| ワークフロー手順を誤る | `.claude/rules/pdca-workflow.md` に明示的なルールを追記 |
| 指示の曖昧さ | 該当スキル（`.claude/skills/<skill>/SKILL.md`）を修正 |
| エージェント選択ミス | `.claude/rules/subagent-selection.md` を更新 |
| Codex MCP ツール失敗 | `.claude/rules/error-recovery.md` にワークアラウンドを記録 |
| 環境・コマンドの問題 | `.claude/rules/operations.md` にワークアラウンドを記録 |

### Step 3: ユーザーへの報告

```markdown
## エラー対応報告

### 発生した問題
- <エラー内容・意図しない挙動>

### 根本原因
- <原因の分析>

### 実施した対応
- <ルール更新内容と対象ファイル>

### 再発防止策
- <更新したルールの要点>
```

## PDCA並列実装時の3回失敗プロトコル

並列issue実装（`/pdca` スキル）中、特定のissueで3回の修正試行が失敗した場合：

### トリガー条件
- Codex が同一issue内で3回の修正を試みて、全て失敗
- Check NG が3回繰り返される、または実装エラーが3回発生

### 対応フロー
1. **Codex が他の並列実行を停止**
   - 実行中の他のissueの処理を中断
   - 失敗したissueの詳細情報（エラーログ・試行内容）を記録

2. **Claude に報告**
   - 失敗したissue名
   - 3回の試行内容と失敗理由
   - 影響を受けた他のissue

3. **Claude が原因分析・再プラン**
   - 要件の曖昧さ / 実装不可能性 / 設計ずれ を判定
   - 必要に応じて要件修正・スコープ削減を実施
   - 新しい実装方針を定義

4. **再開**
   - 再プラン完了後、該当issueを再度Codexで処理
   - 他の並列実行も再開

## 既知のワークアラウンド

### Codex MCP ツール（`mcp__codex-cli__ask-codex`）が失敗する場合

`mcp__codex-cli__ask-codex` は `--full-auto` オプションで CLI エラーが発生することがある。この場合は Bash 経由で直接実行する:

```bash
codex exec --dangerously-bypass-approvals-and-sandbox -C . "<タスク説明>" 2>&1
```

注意: `codex exec` はバックグラウンドで動作することがある。完了確認には:
```bash
# 特定ファイルの生成を待つ場合
until test -f <出力ファイル>; do sleep 3; done
```

### トークンリミット回避

複雑なタスク（認証・複数ファイル・多数の依存ライブラリ）がトークンリミットに達する場合は、段階的タスク分割を適用する（詳細: `.claude/skills/codex-invoke/SKILL.md`）。

## 禁止事項

- エラーを握りつぶして「次のステップ」に進む
- ユーザーに「失敗しました」とだけ報告して終わる
- 同じ失敗を繰り返す（ルール未更新のまま再試行）
- エラー原因を特定せずに対応策を実施する
- ルール更新の前にユーザーへの報告を省略する

## 重要: 新パターンの記録

新しい種類のエラー・意図しない挙動が初めて発生した場合、その対応策をこのファイルの「既知のワークアラウンド」セクションに必ず追記する。
