### 改善3: Phase 2「Do」に「複雑な依存関係の並列度調整」を追加

**課題**: 実行順序が複数段階に分かれている場合の対応が不明確

**改善内容**:
```markdown
【追加セクション】
**複雑な依存関係がある場合の並列度調整**

実行順序が複数段階に分かれている場合、以下のルールで並列度を最適化：

例: issue-A → (B, C) → (D, E) → F という依存チェーン

並列度を高めるには:
- A 完了時に B/C を同時開始（待たない）
- B が C より早く完了しても、D は B 完了後すぐ開始（C と並列可）

並列度を絞るには:
- API仕様の変更が多い場合は、A 完全完了 → B/C を順次実装
```

**効果**:
- エッジケース対応 +2点（複雑な依存チェーン、並列度の判定基準を示唆）
- 実行可能性 +2点（具体的な調整方法を提供）

### 改善4: Phase 5「マージ」に「複数issue統合PR vs 個別PR の判定」を追加

**課題**: PR を統合するか個別にするかの判定基準が不明確

**改善内容**:
```markdown
【新規追加】
### 複数issue統合PR vs 個別PR の判定

**複数issue統合PR を選ぶ場合:**
- issue 間に相互依存がある（API仕様の整合性が重要）
- issue 数が 3 つ以下

**個別PR を選ぶ場合:**
- issue が独立している（依存関係なし）
- issue 数が 4 つ以上
- マージのタイミングが異なる可能性がある
```

**効果**:
- 実行可能性 +2点（判定ロジックの明確化）
- 出力形式の明確さ +1点（PR戦略の可視化）

### 改善5: Issue のライフサイクルに「部分マージのケース」を追加

**課題**: 複数issue並列で一部issueが先に CHECK OK になった場合の対応が不明確

**改善内容**:
```markdown
【新規セクション】
### 部分マージのケース

複数issue並列実装で、一部issueが先に CHECK OK になる場合の対応：

**パターン1: 独立した issue は先行マージ可**
issue-A → CHECK OK → マージ実行 ✅
issue-C（独立） → CHECK OK → マージ実行 ✅

**パターン2: 統合PR を選んだ場合は全 issue が CHECK OK まで待機**
issue-A/B/C が統合PR化
issue-A → CHECK OK ✅
issue-C → Check NG ← 全 issue が CHECK OK になるまで待機
```

**効果**:
- エッジケース対応 +2点（部分マージのシナリオを明示）
- 情報の完全性 +1点（判定フロー図を視覚化）

## 改善ツール: skill-evaluator について

本改善は skill-evaluator（メタスキル）を使用して、以下の手順で実施されました：

1. **採点フェーズ**: 4観点（品質、説明、設計、実行可能性）から複合評価
2. **分析フェーズ**: 最大失点観点（トリガー説明 12/20）を特定
3. **改善案生成**: その観点内で 3～6 の不足項目を洗い出し
4. **優先順位付け**: スコアインパクト × 実装手軽さ で改善順序を決定
5. **実装フェーズ**: SKILL.md に直接反映
