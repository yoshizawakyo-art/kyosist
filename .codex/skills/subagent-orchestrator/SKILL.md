# Subagent Orchestrator

Codex の `spawn_agent` 系ツールを使い、複数エージェントで作業を分担するための運用ガイド。

## Goal

このスキルの目的は次の3つ:
- サブエージェントを呼ぶべき場面だけで使う
- 委譲タスクを小さく、独立し、成果物が統合しやすい形にする
- メインエージェントがクリティカルパスを保持し、待ち時間を減らす

## Trigger

このスキルは、ユーザーがサブエージェント利用を明示した場合に使う:
- 「サブエージェントを呼んで」
- 「複数エージェントで並列に」
- 「explorer/worker に分担して」
- 「調査を別エージェントに任せて」
- 「実装を複数 worker に割って」

ユーザーが単に「詳しく調べて」「徹底的に」「深く分析して」と言っただけでは、このスキルを使わない。

## Workflow

1. ユーザー要求を分解し、即時ブロッカーと並列化できる副タスクを分ける
2. メインエージェントが今すぐローカルで進める作業を1つ決める
3. サブエージェントに渡すタスクを、独立した成果物単位に絞る
4. 調査なら `explorer`、実装なら `worker`、それ以外は `default` を選ぶ
5. 実装を委譲する場合は、担当ファイルまたは担当モジュールを明記する
6. `spawn_agent` 後は待たずに、メインエージェントで非重複作業を進める
7. 必要になった時だけ `wait_agent` で結果を待つ
8. 結果を統合し、不要になったエージェントは `close_agent` する

## Delegation Rules

### Use Subagents When

- ユーザーがサブエージェント利用を明示している
- タスクが独立しており、メイン作業を止めずに進められる
- 調査結果、パッチ、検証結果など具体的な成果物を期待できる
- 複数 worker の書き込み範囲を衝突しないように分けられる

### Keep Work Local When

- 次の一手がその結果に依存していて、待つだけになる
- タスクが曖昧で、委譲先が何をすればよいか定義できない
- 同じ問題をメインとサブエージェントで重複調査するだけになる
- 実装範囲が密結合で、分割すると統合リスクが高い

## Role Selection

| Role | Use for | Expected output |
|---|---|---|
| `explorer` | コードベースの限定調査、設計確認、原因候補の切り分け | 根拠付きの短い調査結果、関連ファイル、次の推奨 |
| `worker` | 独立した実装、テスト追加、局所的な修正 | 変更ファイル一覧、実装内容、検証結果 |
| `default` | 調査/実装に明確に分類できない補助タスク | 指定した形式の成果物 |

## Prompt Template

### Explorer

```text
あなたは explorer サブエージェントです。以下の問いだけを調査してください。

目的:
- <知りたいこと>

範囲:
- 読んでよい主なファイル/ディレクトリ: <paths>
- 変更は行わない

出力:
- 結論
- 根拠となるファイル/関数
- メインエージェントが次に取るべき具体アクション
```

### Worker

```text
あなたは worker サブエージェントです。あなたはこのコードベースで単独ではなく、他の作業者も並行して作業しています。他者の変更を戻さず、必要なら既存変更に合わせてください。

担当:
- <担当ファイルまたはモジュール>

実装内容:
- <具体的な変更>

制約:
- 担当範囲外のファイルは変更しない
- 破壊的コマンドは使わない
- 既存のスタイルとテスト方針に合わせる

完了時の出力:
- 変更したファイル
- 実装概要
- 実行した検証コマンドと結果
```

## Parallelization Pattern

複数のサブエージェントを呼ぶ場合:

1. 先に全体計画を短く作る
2. 各サブタスクの成果物と担当範囲を重複させない
3. 同じ unresolved thread に似た依頼を複数投げない
4. メインエージェントは、サブエージェントの結果に依存しない作業を進める
5. 統合前にサブエージェントの変更ファイルを確認する

## Wait Strategy

- すぐ必要な結果だけ `wait_agent` で待つ
- まだメインで進められる作業があるなら待たない
- 複数エージェントのうち、先に終わった結果だけ必要な場合は複数 target を渡す
- 終了済みまたは不要になったエージェントは `close_agent` する

## Safety

- ユーザーが明示していないのにサブエージェントを起動しない
- 機密情報、秘密鍵、個人情報を不要に渡さない
- 破壊的操作、権限昇格、外部公開を委譲しない
- worker には「他者の変更を戻さない」ことを必ず伝える
- 実装 worker には所有範囲を必ず明記する

## Output Style

ユーザーに計画を見せる場合は、簡潔に次を出す:

```text
サブエージェント計画:
- local: <メインで今進める作業>
- explorer/worker 1: <目的、範囲、成果物>
- explorer/worker 2: <目的、範囲、成果物>
```

実行後の最終報告では、次を短くまとめる:
- メインで行ったこと
- 各サブエージェントの成果
- 統合した変更
- 検証結果
