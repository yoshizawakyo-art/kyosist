# 実装ワークフロー（Codex版）

このリポジトリの実装・修正タスクは、原則として以下の順序で進める。

`Plan -> Do -> Check -> PR -> Review -> Merge`

## 基本原則

- 実装は小さな差分で行い、目的外の修正を混ぜない
- 変更後は必ずローカルで検証してからPRを作る
- レビュー指摘は同一PRに追加コミットで反映する
- 破壊的操作（`reset --hard`、大量削除、履歴改変）は事前にユーザー確認

## フェーズ定義

## 1) Plan

- 要件整理
- 影響範囲の確認（API/UI/DB/設定）
- 実装タスク分割
- 完了条件の定義

## 2) Do

- 方針に沿って実装
- 必要最小限のテスト追加/更新
- ローカルで動作確認

## 3) Check

- 変更差分レビュー（要件適合、設計整合、回帰リスク）
- テスト・lint・formatの結果確認
- UI変更時は画面確認（必要に応じてPlaywright）

## 4) PR

- 変更内容、検証結果、影響範囲をPR本文に明記
- 必要ならスクリーンショット/ログを添付

## 5) Review

- 指摘は重要度順で対応
- 仕様変更が必要になった場合は、先に合意してから修正

## 6) Merge

- 必須チェック通過後にマージ
- マージ後に必要な運用作業（DB反映、環境変数反映）を実施

## リスク別の運用

- 低リスク（文言・コメント・軽微修正）: Planを簡略化可
- 中リスク（UI/API/複数ファイル）: Planと検証手順を明示
- 高リスク（DBスキーマ、認証、外部連携仕様）: ロールバック方針を必須化

## 完了条件

- 要件を満たす実装が反映されている
- 必要な検証コマンドが成功している
- 未解決事項が明示されている（なければ「なし」）
