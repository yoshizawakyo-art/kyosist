# Kyosist アーキテクチャ設計書

**作成日:** 2026-05-04  
**バージョン:** 1.0

---

## 1. プロジェクト概要

### ビジョン
個人が定型業務を自動化し、スキル化して再現性高く自動実行できるアプリケーション。

Manus のように、業務プロセスを「スキル」として記録し、定期実行またはユーザー指示で自動実行する仕組みを提供。

### 対象ユーザー
- 個人が自分の定型業務を自動化したい人
- 同じ操作・フロー作業を何度も繰り返すユーザー

### 成功指標
1. ユーザーがスキルを定義・実行できる
2. 定期実行が安定して動作する
3. UI 操作記録が正確に機能する

---

## 2. 実装アプローチ

### 選択: **Approach A — チャット駆動・段階的実装**

**理由:**
- 現在のチャット・AI エージェント実装が活かせる
- ユーザーが早期に試せる
- 段階的に機能を拡張できる

**全体フロー:**
```
ユーザー（チャット）
  ↓
AI エージェント（自然言語理解）
  ↓
スキル実行エンジン（記録・実行・定期実行）
  ↓
操作実行 + 結果報告（チャットに返す）
```

---

## 3. 全体アーキテクチャ

### システム層構成

**4層構成：**
1. **認証層** — ログイン・サインアップ・パスワードリセット（メール + パスワード）
2. **チャット UI層** — 認証後、ユーザーとの対話入口
3. **AI エージェント層** — 自然言語解釈 → スキル実行指示
4. **スキル実行エンジン層** — スキル定義・保存・実行・定期実行

### データベーススキーマ

#### **users テーブル**
```
id (PK)
email (UNIQUE)
password_hash
created_at
updated_at
```

#### **password_reset_tokens テーブル**
```
id (PK)
user_id (FK → users)
token (UNIQUE)
expires_at
created_at
```

#### **skills テーブル**
```
id (PK)
user_id (FK → users)
name
description (自然言語説明)
operation_log (JSON / TEXT: UI操作記録、Phase 2以降で使用)
created_at
updated_at
```

#### **skill_executions テーブル**
```
id (PK)
skill_id (FK → skills)
user_id (FK → users)
status (pending / running / success / failed)
result_log (JSON: 実行結果・ログ)
executed_at
completed_at
error_message
```

#### **skill_schedules テーブル**
```
id (PK)
skill_id (FK → skills)
user_id (FK → users)
cron_expression (例: "0 9 * * *")
is_active (true / false)
last_executed_at
created_at
updated_at
```

## 5. エラーハンドリング・テスト・セキュリティ

### エラーハンドリング

**認証エラー**
- メール未登録、パスワード不一致 → 「メールまたはパスワードが正しくありません」（詳細を隠す）

**バリデーション**
- メール形式、パスワード強度 → クライアント側で即座にフィードバック + サーバー側で二重検証

**スキル実行エラー**
- 操作失敗、外部 API エラー → チャットでユーザーに報告、ログに記録

**スケジュール実行エラー**
- バックグラウンドジョブ失敗 → ログに記録、次回実行時に再試行

### テスト戦略

- **ユニットテスト** — API ロジック（認証、スキル実行）
- **統合テスト** — DB + API フロー（ログイン→スキル実行）
- **E2E テスト** — ブラウザでユーザーフロー確認（Playwright）

### セキュリティ

**パスワード管理**
- bcrypt で暗号化、salt コスト 12 以上（本番環境）

**認証トークン**
- JWT で署名、有効期限 24 時間
- パスワードリセットトークン有効期限 1 時間

**API通信**
- HTTPS 強制
- CORS 設定（本番では信頼できるドメインのみ）

**入力検証**
- サーバー側で全項目を検証（クライアント検証のみでは不足）

**操作ログ**
- パスワード・トークン・機密情報は記録しない

## 6. 実装の依存関係

```
Phase 1（認証）
  ↓
Phase 2（チャット + スキル基本）
  ↓
Phase 3（UI操作記録）
  ↓
Phase 4（定期実行）
```

各フェーズ内のタスクは並行実行可能（db-architect と backend-specialist と frontend-ui-specialist で同時進行可能）。

## 7. 完了条件（Definition of Done）

### MVP（Phase 1 + 2）完了時点での完了条件

1. ユーザーが登録・ログインできる
2. ログイン後、チャット画面にアクセス可能
3. ユーザーが「〇〇というスキルを実行」と指示できる
4. AI エージェントが指示を理解してスキルを実行
5. スキル実行結果がチャットに返される
6. スキル一覧の表示・削除が正常に機能
7. ユニット・統合・E2E テストが通過
8. セキュリティチェック（パスワード、トークン管理）が完了

### 将来フェーズ（Phase 3, 4）での完了条件

- Phase 3: UI 操作記録が正確に機能
- Phase 4: 定期実行が安定して動作、実行ログが正確に記録される

## 8. 技術スタック

- **認証:** JWT（bcrypt パスワード暗号化）
- **メール送信:** SendGrid / AWS SES（パスワードリセット用）
- **バックグラウンドジョブ:** APScheduler / Celery （定期実行用）
- **データベース:** Supabase (PostgreSQL)
- **フロントエンド:** Vanilla JS （既存フレームワーク）
- **バックエンド:** Python + FastAPI （既存）
