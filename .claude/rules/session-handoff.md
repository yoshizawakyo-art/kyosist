# セッション引き継ぎルール

## トリガー条件

以下のいずれかに該当する場合、**自動的に**引き継ぎドキュメントを作成する：

1. コンテキスト使用量が 95% 以上に達した（残り≤5%）
2. `/compact` コマンドを実行しようとしている
3. 長時間のセッションで新しい調査・実装タスクに移行する場合

## 引き継ぎドキュメント作成の手順

### ステップ1: 状態の整理
以下を**同一ターン内**に完了する：

1. `.claude/doc/pending-tasks.md` を最新状態に更新する
   - 完了したタスク → `## ✅ 完了済み` に移動
   - 未完了タスク → 理由つきで `## 🔲 未完了・引き継ぎ事項` に記入
   - 実装中のPR状況 → PR番号・URL・commit を記録

2. 進行中のプランファイル（`~/.claude/plans/*.md`）を確認
   - 未実装部分がある場合、その状態を更新
   - どこまで完了・未実装か明記

3. git の状態確認
   - 未コミット変更がないか確認
   - あれば commit するか、一時的な変更ファイルとして `.claude/doc/` に記録

### ステップ2: 引き継ぎドキュメント作成

**ファイルパス**: `.claude/doc/handoff-<YYYYMMDD-HHmm>.md`

**形式**:
```markdown
# セッション引き継ぎドキュメント
作成日時: <ISO 8601形式 日時>
引き継ぎ理由: コンテキスト限界 / ユーザー指示 / etc.

## 現在のコンテキスト

### 実施中のタスク
- [タスク名]: [現在の進行状況]
- [関連ファイル]: [パス]

### 完了済みアクション
- [実施日]: [内容]

## 次に実施すべきアクション（優先順）
1. [アクション1]: [詳細]
2. [アクション2]: [詳細]

## 重要な設計判断・制約事項
- [判断内容]: [理由]

## 環境・設定の確認事項
- [ ] Gemini API キーが .env に設定されているか
- [ ] Supabase JWT_SECRET が設定されているか
- etc.

## 関連ファイル・PR
- [PR#123](URL) - マージ済み / マージ待ち
- [Plan](path/to/plan.md) - 進行状況

## メモ・留意点
- [注記内容]

---
**Next Session**: `/resume` で前の session の context を復元可能
```

### ステップ3: ユーザーへの通知

引き継ぎドキュメント作成後、ユーザーに以下を通知する：

```
📋 セッション引き継ぎドキュメントを作成しました。

ファイル: <path>

次のセッション開始時:
1. 新しいセッションで `/resume <path>` で context を復元
2. または `.claude/doc/pending-tasks.md` を確認してから作業再開
```

## 引き継ぎドキュメントの内容ガイドライン

### 必須項目

- **現在のコンテキスト**: 何をしていたか、どこまで進んだか
- **未完了タスク**: 残っているタスクと理由（環境制約 / ユーザー判断待ち / リスク評価待ち）
- **次のアクション**: 優先度順のタスクリスト（新セッション開始時に即実行可能なレベルの粒度）
- **重要な判断**: 設計方針、技術選定、リスク評価などで「次セッションで覆さないでほしい」事項

### 補足項目

- 関連するPR・Issue・branch 情報
- 環境依存事項（API キー、環境変数等）
- テスト・検証で未確認の部分
- パフォーマンス懸念 / セキュリティリスク 等

## 禁止事項

- 完成度の低いドキュメントで引き継ぐ（曖昧な記述）
- 未確認のまま「推測で」次アクションを書く（実施中のコード / テスト結果から事実ベースで記入）
- セッション引き継ぎドキュメント作成時に、同時に新規タスクを開始する（引き継ぎドキュメント完成 → 終了）
- 引き継ぎドキュメント作成後、それでも新しいタスクを開始する

## 同期ルール

- 新セッション開始時、まず `.claude/doc/handoff-*.md` の最新ファイルを読み込む
- `.claude/doc/pending-tasks.md` と handoff ドキュメントの内容が矛盾する場合、handoff ドキュメント（より詳細）を優先
- 前セッションでやり残したタスクは、新セッション開始直後に再評価する（状況変化を確認）

## 複数セッション にまたがるタスクの管理

長期的なタスク（複数日 / 複数セッション）の場合：

1. `.claude/doc/pending-tasks.md` にマスター記録を保持
2. 各セッションの handoff ドキュメントは、その時点での進行状況スナップショット
3. 新セッション開始時、最新の handoff ドキュメント + pending-tasks.md を合わせて読む

例：
- Session 1 終了: `handoff-20260506-1430.md` 作成（AI改善トラック 50% 完了）
- Session 2 終了: `handoff-20260506-1530.md` 作成（AI改善トラック 100% 完了、UI改善開始）
- 常に pending-tasks.md は最新状態に更新
